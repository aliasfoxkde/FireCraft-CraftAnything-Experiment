# Accessibility checklist (Phase 18.6)

Status as of 2026-11-25. Each row names its evidence or its gap.

| Area | Status | Evidence / gap |
|------|--------|----------------|
| Text contrast (WCAG AA 4.5:1) | Covered | `theme.rs` tests assert body text on panel/panel_alt/well/bg, accent labels, dim text 3:1, both themes. |
| Keyboard menu operation | Covered in code, unverified on screen | Alt+letter mnemonics open each menu; Arrow keys navigate within/across; Enter/Space activate; Escape closes (`layout.rs`, `menus.rs`). |
| Keyboard shortcuts, no mouse required | Covered | Full shortcut table in `docs/tutorials/keybindings.md`; dispatch gated on `text_edit_focused()` so typing is never hijacked. |
| Visible focus on WASM | Unverified | No browser session here; egui default focus ring ships. Needs a headless-browser capture. |
| Reduced motion | Partial | App has no autonomous animation loops; splash and spinner are the only motion. A `prefers-reduced-motion` toggle is not implemented — recorded as a limitation, not a defect. |
| Screen readers | Not supported | egui has no platform a11y tree bridge in this build; recorded as a limitation (upstream egui limitation). |
| Tooltips on every icon control | Covered in code | Align/Path/Tools icon buttons all carry `on_hover_text`; no icon-only action without a tooltip was found in the panel bodies. |
| Non-color state signaling | Covered | Collapse state changes chevron glyph, not only color; disabled buttons use `add_enabled` (dimmed + non-interactive). |

## What would close the unverified rows

1. WASM focus visuals: headless-browser screenshot with keyboard-navigated focus.
2. Reduced motion: implement a `prefers-reduced-motion` check guarding the splash
   animation, with a test asserting the static path.
3. Screen readers: blocked on egui upstream (`accesskit` integration); revisit when
   egui ships it.
